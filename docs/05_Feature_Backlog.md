# Feature Backlog

RICE scores are directional prioritization scores for the pilot. They should be recalculated once real reach, impact, confidence, and effort estimates are available.

| Feature | RICE | Status | Why now |
|---|---:|---|---|
| AI Wellness Assessment | 95 | To Do | Core value proposition and primary data-entry point |
| Landing Page | 90 | In progress | Explains value and drives assessment entry |

| Instructor Recommendation | 82 | To Do | Connects personalization to the human teaching model |
| Booking / Consultation CTA | 75 | To Do | Provides a concrete conversion action |
| Static Instructor Profiles | 70 | To Do | Gives recommendations credible context without requiring a full marketplace |
| Basic Analytics | 65 | To Do | Needed to validate the funnel and improve the MVP |

### Phase 1 acceptance principle
A feature belongs in the MVP only when it supports the loop: **discover → assess → personalize → recommend → convert**.

## Deferred deliberately

Complex marketplace mechanics, computer vision, and a native mobile app are intentionally deferred. They add engineering surface area before the pilot proves that users complete the core journey and that instructors/business owners receive measurable value.

## Subscription concept to validate later

The product should not lock pricing before user research, but the initial model to test is a tiered subscription combining content access, personalized plans, and optional instructor support. Pricing will be treated as an experiment rather than a fixed assumption.
